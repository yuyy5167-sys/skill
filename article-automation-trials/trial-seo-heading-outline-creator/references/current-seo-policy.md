# 現在有効なSEO方針

## 採用する原則

見出し設計では、検索エンジンのために語句を並べるのではなく、検索者の目的を満たす、人に役立つ内容を理解しやすい順序で示す。次を基本原則とする。

1. 読者の主質問への答え、範囲、前提を早い位置で明確にする。
2. タイトルとH1は記事内容を正確に表し、誇張・釣り・実態のない比較最上級を避ける。
3. H2・H3は論理的な階層にし、同じ問いへの重複回答や見出しだけの水増しをしない。
4. キーワードは、必要な文脈で自然に使う。語順違い、同義語、関連語を機械的に反復しない。
5. 競合との差分は、レポートで確認できる読者価値がある場合だけ設ける。根拠のない独自性は作らない。
6. 正確性・鮮度・一次情報が重要な章は、上流レポートの根拠と不明点を引き継ぐ。見出しだけで未確認事実を確定させない。
7. AI検索向けに特別な見出し記法を狙わない。通常の検索者が理解しやすい、明確で根拠のある構成を優先する。

特定のH2数、H3数、本文文字数、キーワード出現回数、FAQ数をSEO順位の必達ルールにはしない。必要性・理解しやすさ・重複のなさを優先する。後述するタイトル文字数はSEO順位要因ではなく、ユーザーが採用した編集方針として扱う。

## 編集方針としてのタイトル・見出し基準

### キーワード区分

- `target_query`は、ユーザーが最初に提示した検索語全体であり、途中で短い別表記へ置き換えない。
- `main_keyword`は記事が直接答える中心語句、`required_subkeywords`は対象者・用途・条件・悩みなど、タイトルと見出しで必ず回収する語句とする。
- `optional_related_terms`は、検索意図と文章の自然さに合う場合だけ使用する。必須語の代わりにはしない。
- 空白で区切られた検索語や、複数列挙されたキーワードでは、`input-contract.md`に従って区分を固定してから構成を作る。

### 記事タイトル

- 3候補すべてに`main_keyword`と全`required_subkeywords`を含める。一つの検索語として提示された場合は実質語の順序を保ち、複数キーワードとして提示された場合は自然な語順へ調整できる。空白の削除や助詞の追加は認めるが、必須語の削除や一般化は認めない。ユーザーが完全一致を指定した場合はその指定を優先する。
- 32文字前後を目標にし、30〜34文字を推奨、28〜36文字を許容範囲、原則40文字以内とする。
- 日本語、英数字、空白、句読点、記号を表示上の1文字として数える。絵文字や結合文字は表示上の1文字として扱う。
- キーワード自体が長く40文字以内に収められない場合、勝手に省略しない。40文字超過の承認がなければ`needs_user_decision`とする。
- 記事の中心的な問いまたは判断対象を示し、見出しで回収できない内容を約束しない。
- 評価姿勢を示すためだけに「第三者」などの語を機械的に入れない。ただし、指定キーワードまたはユーザー指定に含まれる場合は除く。

### 数字を使うタイトル・見出し

数字は、使用自体を目的にせず、非数字表現より一覧性、具体性または手順理解を改善する場合だけ使う。数字や目標件数を先に決めて、`required_answers`や見出しを分割、統合または追加してはならない。現在の`content_source`だけから、次のように分類する。

- `structural_count`: 最終構成で提示する、相互に区別できる項目の件数。構成確定後に数え、重複や水増しがないことを確認する。
- `ordered_sequence`: 前後関係または依存関係を持つ手順の順番と総数。並べ替えても理解や実行に影響しない項目には使わない。
- `factual_number`: 割合、金額、期間、年、人数、点数、順位など、外部世界についての数値主張。
- `numeric_keyword`: `target_query`、`main_keyword`または`required_subkeywords`に元から含まれる数値語。任意候補ではなく、K2に従って保持する必須語として扱う。

数字でない量感表現、過去の実行例、別タスクの指摘、競合が採用した件数は数字候補にしない。`numeric_keyword`以外の数字は任意候補であり、使わなくても正確な構成を作れる場合は無理に使わない。

`factual_number`は、構成を作る前に原資料、時点、単位、対象範囲、必要な分母と、主張する範囲に対する根拠強度を確認する。

- `strong`: 一次資料または原資料まで追跡でき、対象、期間、定義、条件を裏付ける。調査値では対象集団、標本規模、抽出・収集方法、代表性、明示された限界を確認し、記事で示す範囲への一般化を妨げる問題がない。料金、期間、仕様などでは、現行の公式または同等の原資料で適用条件を確認できる。
- `limited`: 出典は確認できるが、対象範囲が狭い、代表性が不明、調査方法が不十分、時点が古い、定義がずれるなど、限定条件なしの主張には使えない。
- `insufficient`: 元資料へ追跡できない、分母・単位・対象・時点・方法の重要部分が不明、または異なる範囲へ読み替えている。

タイトル、H1、H2、H3の数字表現に使える`factual_number`は`strong`だけとする。公式という名称だけで`strong`にせず、主張範囲との対応を確認する。固定の標本数や一律の有効期限は設けない。主質問への回答に事実数値が不可欠なのに`strong`な根拠がなければ`needs_research`とし、不可欠でなければ数字候補から外して進める。

任意数字をタイトルに使う前に、次の三段階で判定する。

1. `source_valid`: 現在入力から数字を正しく確定できる。`factual_number`は`strong`である。
2. `title_relevant`: 数字が`primary_information_need`またはタイトルの中心価値に直接関係し、非数字表現より短時間で内容を理解できる。必要な単位、範囲、条件を省かない。
3. `candidate_valid`: 実際の数字入り候補が、既存のタイトル個別ゲート、K1〜K4、40文字以内、全必須語、自然さ、正確性、非誇張、構成との一致をすべて満たす。

`candidate_valid`な数字入り案が一つ以上ある場合、タイトル3候補の少なくとも一つで使う。必須語群に`numeric_keyword`が存在しない場合は、少なくとも一つを非数字表現にして比較する。`numeric_keyword`が存在する場合は3候補すべてで保持し、非数字候補を要求しない。推奨タイトルは数字の有無だけで決めず、品質が同等なら一覧性を改善する数字案を優先できる。

親見出しで件数を示す場合は、直下または明示した対象項目数と一致させる。順序番号は実質的な順序があるグループだけに使い、同一グループ内の表記を統一する。構成変更後は数字を再抽出・再集計し、件数、順序、値、単位、時点、対象範囲、条件が最終構成と一致しなければ、数字を更新または撤回する。

### 必須サブキーワードの見出し配置

- 各`required_subkeyword`は、H1・H2・H3のいずれか一つ以上に含める。対象者を示す語は対象・条件・適否を扱う見出し、用途や悩みを示す語は答えを扱う見出しへ置く。
- 見出しに語を入れるだけでなく、その配下の本文役割と根拠がサブキーワードへ実質的に答える構成にする。
- 同じ必須語を全見出しへ繰り返さない。必要な見出しへ一度以上配置できれば、残りは自然な表現を優先する。
- 必須サブキーワードを扱う根拠が上流レポートにない場合は、語だけを挿入せず`needs_research`とする。
- 40文字以内のタイトルや自然な見出しと両立できない場合は、勝手に削除せず`needs_user_decision`とする。

### 見出しの読者価値

- 各H2に、その章で答える検索者自身の疑問`reader_question`と、読後に可能になる理解・判断・実行`reader_outcome`を一つ以上対応させる。
- 見出しの興味は、刺激的な語ではなく、自分に関係する答え、判断材料または次の行動が見えることで作る。根拠のない効果、優位性、緊急性で補わない。
- 注意事項や根拠上の留保を見出しへ詰め込み、中心的な答えを隠さない。読者の判断に不可欠な条件だけを見出しへ残し、詳細な出典確認や留保は本文冒頭または注意箇所で扱う。
- 「確認する」「確かめる」「調べる」などの語は、読者が行う具体的な確認や検索意図そのものが手順である場合に使える。執筆者の調査作業だけを示し、読者の到達状態を説明できない場合は不合格とする。

### H2

- 対応する`reader_question`と`reader_outcome`を持ち、「扱う内容」と、疑問・条件・対比・判断・影響のいずれかを示して、読む理由と読後の到達状態が伝わる見出しにする。
- 「料金」「使い方」「メリット」などの分類名だけ、または「〜を評価」「〜を解説」の機械的な反復を不合格とする。
- 執筆者の確認・調査・検証を報告するだけの見出しにしない。読者が得る答え・判断・行動のいずれかを説明できない場合は再設計する。
- 原則として記事タイトルより短くする。18〜30文字程度は参考範囲であり、必達値にはしない。
- 内容と読む理由を先に確定し、その後に冗長語だけを削る。短縮で意味や興味が失われる場合は、章の役割・分割・タイトルとの関係から再設計する。
- 同じ疑問形や語尾が3件以上連続する場合は、意図的な一覧構造を除き、単調さと役割重複を見直す。

### H3

- 親H2の根拠、条件、具体例、手順、注意点のいずれかを具体化する。
- H2と同じ結論を繰り返さず、親H2から外れた別テーマを扱わない。
- 興味表現や一定文字数を強制せず、具体性と親子関係を優先する。
- 執筆者の確認作業だけを示さず、親H2の`reader_outcome`へどう寄与するかを説明できる見出しにする。

### 記事モード別の適用

- `evaluation_decision`と`comparison`では、メリットと弱点、向く利用者と向かない利用者、公式情報と記事側の判断の区別を必須にする。
- `how_to`と`factual_explainer`では、評価章を無理に足さず、前提条件、例外、失敗しやすい点、確認方法を優先する。ただし確認方法を執筆者の作業報告にせず、読者が何を判断または実行できるかを見出しに残す。
- 評価・比較系では、異なる意思決定に影響する、根拠付きの独立した判断材料を2つ以上設ける。同じ注意点の言い換えは複数に数えない。根拠が2つ未満なら創作せず`needs_research`とする。

## 設計時の実践ルール

| 観点 | 行うこと | 行わないこと |
|---|---|---|
| 意図 | 主意図に直接答える章を前半に置く | 前置きで答えを遅らせる |
| タイトル | 対象者・判断対象・得られる答えを具体化し、主キーワード・全必須サブキーワード・文字数を3候補すべてで確認する | 必須語の省略、「絶対」「完全」「必ず」など根拠のない断定、見出しで回収しない約束 |
| H1 | 記事の中心課題と範囲を一文で示す | タイトルの機械的な複写 |
| H2/H3 | H2は`reader_question`と`reader_outcome`、内容と読む理由を持たせ、H3は親H2の到達状態を具体化し、必須サブキーワードの被覆先を明確にする | 分類名だけのH2、執筆者の確認作業だけの見出し、語だけを置いた被覆、別テーマの混在、階層のためだけのH3 |
| 難易度 | ペルソナが理解できる語を使い、必要な語は説明する | 略語・専門語・抽象語を説明なしに連続させる |
| 差分 | 競合で不足している判断材料を根拠付きで補う | 競合を根拠なく否定する、無関係な章を足す |
| 信頼性 | 根拠が必要な箇所を明示し、未確認は未確認として残す | 価格・制度・効果・順位などを見出しで断定する |

## 根拠の優先順位

SEOの一般方針は、Google Search Central の公式ドキュメントを優先する。テーマ固有の正確性は、上流レポートで確認済みの公式・公的機関・一次資料を優先する。一般ブログやSNSの記述は、検索者の言い回しや疑問の把握には使えても、事実の根拠としては扱わない。

- [Google Search の有用で信頼性の高い、ユーザー第一のコンテンツ](https://developers.google.com/search/docs/fundamentals/creating-helpful-content?hl=ja)
- [Google Search のタイトルリンクに関するベストプラクティス](https://developers.google.com/search/docs/appearance/title-link?hl=ja)
- [Google Search の構造化データに関する一般ガイドライン](https://developers.google.com/search/docs/appearance/structured-data/sd-policies?hl=ja)
