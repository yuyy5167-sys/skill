# 入力契約と停止条件

## 受け取るもの

このスキルの唯一の調査入力は、完了済みの `seo-keyword-competitor-research` レポートである。レポートの本文、または内容をすべて確認できるローカルファイルを受け取る。要約だけ、見出し候補だけ、口頭の結論だけでは開始しない。

| 必須情報 | 上流レポート内の主な位置 | 見出し設計での用途 |
|---|---|---|
| 対象キーワード・調査日・検索条件 | 1. 検索条件 | 対象、語句構成、鮮度の確認 |
| 完了性・信頼度・未確認事項 | Quality Gate、13. 根拠・不明点 | 作成可否の判定 |
| 主・副・除外検索意図 | 8. 検索意図 | 範囲、章順、除外の反映 |
| ペルソナ・悩み・到達点 | 9. 想定ペルソナ | 難易度と訴求の判定 |
| SERP・競合・不足 | 3〜7、10. 参入余地 | 差分と過不足の判定 |
| 一次情報・根拠URL | 7、13 | 事実章や注意点の根拠 |
| 記事方針の推奨 | 2、11 | 新規／既存／停止の判定 |
| 既存記事の実装前提 | 11、またはユーザー提供 | 統合・リライトの対象確定 |

レポートの「12. 記事構成案」に含まれるタイトル・H2・H3は、上流調査時点の仮説である。検索意図、ペルソナ、根拠、差分に照らして再設計し、無批判に流用しない。

## キーワードの分解と固定

見出し設計を始める前に、ユーザーが最初に提示した表記と上流レポートを照合し、次の4項目を固定する。

- `target_query`: ユーザーが提示した検索語全体。空白を含む元表記を保持する。
- `main_keyword`: 記事が直接答える中心語句。
- `required_subkeywords`: タイトルと見出しで必ず回収する補助語句。
- `optional_related_terms`: 意味が合う場合だけ使う関連語。必須語として扱わない。

ユーザーが主キーワードとサブキーワードを明示した場合は、その区分をそのまま採用する。区分の明示がない場合は、次の順で判定する。

1. 空白で区切られた一つの検索語は、全体を`target_query`として保持し、中心となる固有名詞・商品名を`main_keyword`、対象者・用途・条件・悩みを示す残りの実質語を`required_subkeywords`とする。
2. 改行、読点、カンマなどで複数のキーワードが列挙された場合は、先頭を`main_keyword`、残りを`required_subkeywords`とする。ただし、ユーザーが「候補」「関連語」「任意」と示した語は`optional_related_terms`へ移す。
3. 助詞、句読点、検索用の空白は必須語に数えない。複合固有名詞は意味を壊して分割しない。
4. 区分によって検索意図やタイトルの対象が変わる場合は、推測せず`needs_user_decision`を返す。

固定後は、タイトル候補を作る前にキーワード対応表を作成する。ユーザーの承認なく、文字数調整を理由に`main_keyword`または`required_subkeywords`を削除・一般化・別対象へ置き換えてはならない。

## 上流レポートの再確認

次のすべてを確認できるときだけ、`research_ready` とする。

1. `target_query`、`main_keyword`、`required_subkeywords`、調査日、検索条件が特定できる。
2. 上流の Quality Gate が `PASS`、または未解決事項が見出し設計を左右しないと根拠付きで判断できる。
3. 主検索意図、ペルソナ、記事方針の推奨が確認できる。
4. 差分候補または「根拠不足で差分を置かない」という判断根拠が確認できる。
5. 推奨に応じた実装前提がそろっている。

| 状態 | 条件 | 応答 |
|---|---|---|
| `research_ready` | 上記を満たす | 見出し設計に進む |
| `needs_research` | 意図・根拠・鮮度・競合差分のいずれかを確認できない | 必要な再調査項目を返す |
| `needs_user_decision` | キーワード区分、既存記事の対象、統合範囲、上流方針の扱いが未確定 | 必要な判断を返す |

調査日が現在の検索状況や制度・商品仕様に耐えない可能性がある場合は、古いと断定せず「鮮度の再確認が必要」として `needs_research` にする。鮮度の許容期間を固定日数で決めず、キーワードの変動性、検索結果、法令・料金・商品などの更新可能性で判断する。

## 記事方針の推奨と開始可否

上流レポートの `記事方針の推奨` は、次の6つのいずれかである。表にない推奨値は、推測で読み替えず `needs_user_decision` にする。

| 推奨値 | 構成を作れる条件 | 条件不足時の応答 |
|---|---|---|
| `新規作成` | 主検索意図、対象範囲、根拠が確認できる | `needs_research` |
| `既存記事へ統合` | 対象URLまたは記事ID、現行見出し、統合範囲がある | `needs_user_decision` |
| `既存記事をリライト` | 対象URLまたは記事ID、現行見出し、変更範囲がある | `needs_user_decision` |
| `意図を分けて新規作成` | 作る意図・除外する意図・各記事の範囲が明確 | `needs_user_decision` または `needs_research` |
| `別キーワードを検討` | 原則として作成しない | `needs_user_decision` |
| `追加確認` | 原則として作成しない | `needs_research` |

ユーザーが上記の停止推奨を明示的に上書きした場合は、`user_override: true`、上書き対象、理由、残るリスクを記録して構成を作れる。ただし、上書きは不足している調査根拠を補うものではない。不足が安全な構成に影響するなら、上書き後も `needs_research` を優先する。

## 入力不足時の質問

不足を見つけたら、最小限の質問だけを返す。キーワード区分が曖昧なら、主キーワードと必須サブキーワードの確認を求める。既存記事の統合なら「対象URL（または記事ID）」「現行見出し」「残す／置換する範囲」を求める。調査不足なら、再調査すべき検索意図・競合差分・一次情報・鮮度を具体的に示す。

入力確認の段階で停止する場合、仮のタイトルや完成見出しは出さない。未検証の構成案が完成品として流用されることを防ぐためである。
