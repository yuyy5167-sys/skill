# 出力形式

## 共通ルール

- 先頭に `status` を置く。値は `PASS`、`needs_research`、`needs_user_decision`、`iteration_limit_reached` のいずれかにする。
- 見出しを作成した場合だけ、タイトル候補、H1、H2、H3を出す。
- 構成方針として `outline_mode` を記録する。値は `evaluation_decision`、`comparison`、`how_to`、`factual_explainer` のいずれかにする。
- 見出しは安定IDを付ける。形式は `H1-01`、`H2-01`、`H3-01-01` とする。
- 各根拠は、上流レポートの節名、項目名、またはレポートに含まれる一次情報URLで示す。根拠のない推測を「根拠」と書かない。
- ユーザーが上流方針を上書きした場合は、`user_override: true` とし、対象・理由・残るリスクを必ず記載する。
- タイトル3候補には文字数を付ける。文字数は、表示上の日本語、英数字、空白、句読点、記号を各1文字、絵文字や結合文字を画面上の1単位につき1文字として数える。
- `target_query`、`main_keyword`、`required_subkeywords`、`optional_related_terms`を明示し、タイトル3候補とH1〜H3の必須語被覆を表で示す。
- 記事内容の根拠となる`content_source`、`target_outcome`、`primary_information_need`、`required_answers`を明示し、各要件を現在入力と見出しまで追跡できるようにする。
- 各H2に、その章で答える検索者自身の疑問`reader_question`と、読後に可能になる理解・判断・実行`reader_outcome`を明示する。
- 現在入力から確認した数字候補を、使用・不採用の両方を含めて監査表に記録する。数字候補がない場合も、候補なしと非強制を記録する。
- 予想文字数は50文字単位で、導入文、各H2、記事全体の `最小 / 目標 / 最大` を出す。記事全体の最小値と最大値は各区分の合計と一致させる。

## PASS時のテンプレート

```markdown
status: PASS
対象キーワード: [入力から転記]
target_query: [ユーザーの元表記]
main_keyword: [中心語句]
required_subkeywords: [必須サブキーワードの配列]
optional_related_terms: [任意関連語の配列。なければ空]
調査日: [入力から転記]
記事方針: [新規作成など]
outline_mode: [evaluation_decision / comparison / how_to / factual_explainer]
user_override: false

### 1. 入力・方針の確認
| 確認項目 | 判定 | 根拠 | 補足 |
|---|---|---|---|
| 上流リサーチ完了性 | PASS | [Quality Gate等] | |
| キーワード区分 | PASS | [ユーザーの元入力と上流レポート] | [主・必須サブ・任意の区分] |
| 鮮度・不明点 | PASS | [調査日・不明点] | |
| 記事方針の実装前提 | PASS | [推奨・URL等] | |
| 構成モード | PASS | [検索意図と選定理由] | [選択したoutline_mode] |

### 2. 設計方針
- 主検索意図: [内容]
- 副検索意図: [内容]
- 除外する意図: [内容]
- 主キーワード: [main_keyword]
- 必須サブキーワード: [required_subkeywords]
- 任意関連語: [optional_related_terms]
- ペルソナ: [一文]
- content_source: [現在の対象クエリ、上流リサーチ、現在タスクの明示条件または上書き]
- target_outcome: [読後に到達させる状態]
- primary_information_need: [対象クエリに対して最初に答える情報要求]
- 採用した差分: [内容と根拠] / 差分を置かない理由: [内容]
- 第三者としての判断方針: [事実と編集判断の分け方。評価・比較型の場合は公平性の方針]

### 3. タイトル候補
1. [候補]（[00]文字）— [訴求と根拠]
2. [候補]（[00]文字）— [訴求と根拠]
3. [候補]（[00]文字）— [訴求と根拠]

推奨タイトル: [候補番号と本文]（[00]文字）
推奨理由: [検索意図・内容一致・興味・正確性・差分の観点]

#### タイトル必須語チェック

| 候補 | main_keyword | required_subkeywords全件 | 欠落語 | 文字数 | 判定 |
|---|---|---|---|---:|---|
| 1 | PASS | [PASS/NA] | なし | [00] | PASS |
| 2 | PASS | [PASS/NA] | なし | [00] | PASS |
| 3 | PASS | [PASS/NA] | なし | [00] | PASS |

`required_subkeywords`が0件の場合だけ`NA`にできる。1件以上ある場合は、全件を照合して一語でも欠ければ`FAIL`とする。

#### 数字候補監査

数字を使った結果だけでなく、不採用にした候補と理由も記録する。別タスクの例や競合が使った件数を候補として転記しない。

| 候補ID | 表現候補 | 種類 | current_input_basis | evidence_strength | source_valid | title_relevant | candidate_valid | 使用場所 | 不採用理由 | 構成再集計 | 判定 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| NUM-01 | [数字表現。候補なしの場合は「該当なし」] | [structural_count / ordered_sequence / factual_number / mandatory_by_keyword] | [現在入力またはユーザー元表記] | [strong / limited / insufficient / NA（構成由来） / NA] | [PASS/FAIL] | [PASS/FAIL/NA] | [PASS/FAIL/NA] | [タイトル/H1/H2/H3 IDまたは不使用] | [不使用理由。使用時は該当なし] | [件数・順序・値・条件の再確認結果] | [PASS/FAIL] |

- `structural_count`と`ordered_sequence`の`evidence_strength`は`NA（構成由来）`とする。
- `factual_number`は`strong / limited / insufficient`を記録し、タイトル・H1・H2・H3へ使えるのは`strong`だけとする。
- `mandatory_by_keyword`は`evidence_strength`、`title_relevant`、`candidate_valid`を`NA`とし、K2・K3の保持先を`使用場所`へ記録する。
- 構成修正後に全候補を再抽出・再集計し、古い件数、順序、値、単位、時点、対象範囲、条件が残っていれば`FAIL`とする。

予想文字数には、本文段落、リスト、表の説明文、補足枠、H3配下の本文を含める。タイトル、見出し文字、frontmatter、画像alt、内部管理用メモは含めない。

### 7. 必須回答要件・意図・根拠の対応

値を記入した事例や、別タスクの論点を転記しない。各行は現在の`content_source`だけから作成する。

### 8. 独立した判断軸

`evaluation_decision` または `comparison` の場合は2件以上を記載する。同じ論点の言い換えは別軸に数えない。それ以外のモードでは「対象外」とし、検索意図に必要な手順・条件・例外などを記載する。
```

## 停止時のテンプレート

入力確認または修正上限で停止したときは、完成見出しを出力しない。

```markdown
status: [needs_research / needs_user_decision / iteration_limit_reached]
対象キーワード: [確認できる場合のみ]
target_query: [確認できる場合のみ]
main_keyword: [確認できる場合のみ]
required_subkeywords: [確認できる場合のみ]
optional_related_terms: [確認できる場合のみ]
記事方針: [確認できる場合のみ]
outline_mode: [判定できる場合のみ]

### 停止理由
- [根拠付きの理由]

### 不足または未解決の情報
| 項目 | なぜ必要か | 次に必要な行動 |
|---|---|---|

### 確認済みの前提
- [確認できた意図・推奨・根拠]

### 判定済みの例外
- [主・必須サブキーワードの区分が曖昧、全必須語を40文字以内に自然に収められない、必須サブキーワードを扱う根拠がない、評価・比較型の独立した判断軸が2件未満など]

### 次の工程
- `needs_research`: `seo-keyword-competitor-research` で [具体的な再調査項目] を確認する。
- `needs_user_decision`: ユーザーが [対象URL、統合範囲、キーワード表記、記事方針など] を決める。
- `iteration_limit_reached`: 構造的な再設計後も残った [未解決の根本原因] と、既存根拠内で改善案が尽きた理由を示す。
```

## 出してはいけないもの

- 入力不足時の「仮の完成構成」
- レポートにない順位、価格、制度、効果、競合比較の断定
- 実行していない検索、読了テスト、修正ループを実行済みとする記録
- 実行していない修正回数を埋めた架空の履歴
- 導入文と各H2の合計に一致しない記事全体の予想文字数
- 評価・比較型で、同じ論点の言い換えを独立した判断軸として数えること
- タイトル候補から主キーワードまたは必須サブキーワードを一語でも省略すること
- 必須サブキーワードをH1・H2・H3のどこにも配置しないこと
- 見出しに必須語だけを置き、配下でその検索意図へ答えないこと
- `reader_question`または`reader_outcome`がないH2を`PASS`にすること
- 執筆者の確認・調査・検証作業だけを示し、読者が得る答え・判断・行動を説明できないH2またはH3を`PASS`にすること
- 根拠のない効果、優位性、緊急性で見出しの興味を補うこと
- 現在入力にない数字、別タスクの数字、競合が使った件数をタイトルや見出しへ転用すること
- 数字に合わせて項目を水増しし、親見出しの件数と子項目数、または手順総数と順序が一致しない構成を`PASS`にすること
- `limited`または`insufficient`な事実数値を、タイトル・H1・H2・H3の数字表現へ使うこと
- ユーザー承認のないファイル保存・投稿・既存記事更新の完了報告
