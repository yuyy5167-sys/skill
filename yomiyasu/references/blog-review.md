# ブログ文章の確認

## 通常の文章確認

読者、主質問、素材、保持対象、今回の担当範囲を基準にする。項目を埋めることや、短さ・得点・修正回数で合否を決めない。

1. **答えと判断過程**：執筆前に定めた読者の主質問と誤解防止の問いへ、本文だけから答えを取り出す。対象読者が知らない前提を評価者の知識で補わない。日付等の答えがあるだけでなく、必要な場面ではどう導いたかが追えるか。
2. **説明の順序と密度**：必要な定義・条件が先に分かり、前の文から次へ移る理由が読めるか。一段落に一つの理解のまとまりがあるか。長さだけで分割せず、必要な意味確認は残す。
3. **意味と根拠**：新規は資料、改稿は原文と資料に照合する。主張、比重、確実性、文の働き、主体、対象、時、数量・単位、否定、比較条件、因果・順序を確認する。例や提案を事実・成果保証へ変えない。
4. **見出し・表・要約と途中読み**：入口での断定を本文の留保だけで済ませない。FAQは当該回答だけでも対象条件を追えるか。必要な再掲を重複として消さない。
5. **丁寧な日本語**：主述・修飾・指示語・接続が明確で、ラフな口調、空疎な文、語尾の機械的な変更がないか。意味のある対比、正式名称、引用を守ったか。
6. **必要な説明量**：「削ると何が分からないか」「足すと何が分かるか」で確認する。すでに良い原文を維持する判断も認める。
7. **依頼範囲と出力**：固定構成、部分修正、仮レイアウト、本文のみを守る。未読の全文・未確認の事実・未実行の検査を確認済みにしない。保持するリンク・引用等が指定されていれば照合する。

修正が必要なら、場所／読者への影響／原因／保持条件内の修正を特定する。意味や順序を直した後に前後を読み、構成を変えたときは全体を再確認する。新たに生じた条件脱落等も直す。同じ表現を往復するだけなら原因を見直し、根拠・指定・範囲の不足で解消できない点を残したまま合格にしない。

部分入力では、提供された範囲と確認できる前後だけを評価する。足りない前後が意味を左右する場合だけ、その部分を確認する。小さな不足で全体の作業を止めない。

## 既存スクリプトの使い方

全文の作成・改稿、ファイル保存、または検査を求められたときは、Pythonが利用可能なら補助検査を行う。新しいテスト基盤や自動修正器は作らない。一時的な原文・候補・結果は作業フォルダの既存の一時フォルダにまとめ、公開原稿を検査用に上書きしない。

スキルの配置先から絶対パスを解決する。例の `<skill-dir>` とファイル名は実在するものへ置き換える。

```text
python3 <skill-dir>/scripts/yomiyasu_lint.py <候補.md> --json
python3 <skill-dir>/scripts/yomiyasu_diff.py <原文.md> <候補.md> --stance=説明 --json
```

- Lintは標準入力でも使える。差分検査は原文がある場合に使う。新規執筆で原文がないときは、資料と本文の主張・条件を照合し、原文との差分を確認したとは言わない。
- `--stance` は文書の主な働きから選ぶ。説明・勧め・決まりのどれかを判断できないときは省略する。記事内の異なる働きの文を一つの語尾へそろえない。
- 原文と候補の比較範囲・表現形式をそろえる。原文のHTML、画像、広告コードと本文だけの候補の差を、事実の欠落と機械的に数えない。書式やリンクを保持する依頼では、それらの保持を別に照合する。
- 警告は見直し候補。旧来の箇条書き比率、太字頻度、定型文検出等をブログの合否基準にしない。警告ゼロにするために必要な説明や対比を削らない。
- 追加語・削除語が検出されても意味の変化とは限らない。逆に、同じ語が残っていても、条件の掛かり先や比較対象が変わっていないか確認する。
- 表示上の不備を直す際も、強調の範囲やリンク先を変えない。Lintは完全なMarkdownレンダラーではなく、実際のサイト表示を検証済みにするものではない。
- Pythonが使えなければ同じ観点で目視確認する。検査失敗や未実行を実行済み・合格と報告しない。

## スキル編集後の検証用ケース

ここからはスキルを編集したときの確認に使う。通常の記事執筆では毎回実行しない。各ケースの依頼と素材から実際に出力し、保持条件と読者が理解できる内容で確認する。模範文との文字列一致や指摘件数は合否基準にしない。

数値や仕様は検証用の仮定・固定素材で、実在商品の現在の情報ではない。ケース内に足りる情報があれば外部調査は不要。同一AIで行う確認と独立検証、実読者テストは区別する。

| ID | 依頼・素材 | 確認する結果 |
| --- | --- | --- |
| C01 | 「この説明を丁寧に。本文のみ」。原文「12月号から止めるなら期限は11月1日」。素材「通常は最初に受け取らない月号の前月1日。11月号まで受講する例。4月号は別条件で、この節の対象外」 | 最後の受講月号と最初の停止月号を区別し、11月1日を導く過程を説明する。全月号への一般化、別の費用、編集報告を足さない |
| C02 | 「必要なところだけ読みやすく」。原文「12か月分を一括で支払う場合、総額は24,000円です。月あたりに換算すると2,000円ですが、実際の支払いは24,000円の一括払いです」 | 既に理解できる区別を維持。毎月請求へ変えず、例や注意を無理に追加しない |
| C03 | 「保護者向けに二つの教材を比較する短い本文」。仮定「Aは月額3,000円、動画のみ。Bは月額5,000円、動画と質問対応。ともに同学年、同じ申込経路、税込、追加費用なし。他の仕様や成果は不明」 | 同条件の料金と質問対応を比較し、必要な機能による選択を説明する。Bなら成績が上がる等を作らない |
| C04 | 「高校生向けに、解き直しの方法を書いて」。素材「間違えた問題を一つ選び、解説で止まった箇所を確認し、解答を隠して再び解き、同じ箇所を進められるか確かめる方法を提案する」 | 誰が何をどう確認するかを説明。保護者への命令や、成果保証、架空の研究を追加しない |
| C05 | 「このFAQだけ整えて。ほかの質問は追加しない」。原文「Q. オフラインで使えますか。A. 保存済みの動画は見られます。新しい動画の取得と質問送信には通信が必要です」 | 一問だけでも範囲が分かる。不要な導入・締め・行動案を足さず、オンラインが必要な操作を残す |
| C06 | 「見出しはそのまま、本文だけ自然に」。見出し「締切は、最初に受け取らない月号から考える」。本文はC01の固定素材 | 意味のある説明型見出しを保ち、項目名へ自動短縮しない |
| C07 | 「この文の表現だけ整えて」。原文「この方法は、復習を続ける助けになる可能性があります」 | 可能性と範囲を保持。断定、提案の追加、日数、研究や体験を作らない |
| C08 | 「仮レイアウトだけ。全文は書かない」。テーマ「教材AとBの比較」、素材はC03 | 見出しと各節の問い・説明内容を提示して止める。記事全文や保存・公開へ進まない |
| C09 | 「自分への返金額を本文だけで説明して」。素材「返金額は受講期間と支払内容で変わる。本人の契約・支払額は未提供」 | 金額を創作しない。特定に必要な情報を短く確認する。『要確認』を埋めた完成風の本文を返さない |
| C10 | 「見出し『いつでも無料で解約できる』は一字も変えず、記事を正確にして」。素材「条件によって端末代が掛かる」 | 見出しと素材の衝突を示す。本文末尾の注意だけで全体合格にしない。勝手に固定見出しを変更しない |
| C11 | 「本文だけ自然に」。本文「公式の案内は次のとおりです。『手続き期限は前月1日ですな。』」。引用文の変更は禁止 | 地の文と引用を区別し、引用の口調を勝手に書き換えない。地の文へ口癖を広げない |
| C12 | C01〜C07から作った本文にLintを適用し、原文がある改稿ではDiffも使う。新規の本文は資料と照合する | 必要な否定対比や説明が警告に出ても保持できる。点数だけで合格とせず、未実行を実行済みにしない |

構成から見直す依頼では、過去の承認だけを理由に変更を止めない。一方、部分入力では未読の全文を合格にしない。この違いも出力範囲で確認する。

全体確認には、入手できる場合は承認された解約記事の本文を一時コピーとして使い、主回答・締切の基準・通常条件と例外・端末代と返金・端末と教材期限の区別が最後まで残るかを確認する。料金・期限等の当時の固定素材として扱い、現在の情報を再検証したとは報告しない。入手できなければ、提供された記事全文とその保持条件で同じ観点を確認し、承認稿で検証したとは言わない。公開ファイルは変更しない。
