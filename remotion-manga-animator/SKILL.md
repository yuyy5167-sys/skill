# 漫画のRemotionアニメーション

原稿の読み順、人物の顔、表情、服、文字を維持し、各コマの意味に合う小さな動作を付ける。単なる全画面ズームだけで人物が動いたと扱わない。

## 依頼と入力

- 設計のみの依頼ではチャット内で設計を提示する。制作を依頼・承認されたら、必要な試作から本編、確認、納品まで進める。途中の段階ごとの再承認を定例化しない。
- 全ページの実画像を確認し、対象作品、読み順、セリフ、持ち物と前後関係を整理する。OCRやファイル名だけで確定しない。判別できない読み順や欠けた原稿など、結果を左右する不足だけ確認する。
- ユーザーの指定を優先する。今回の会話で決まった音や尺を、無関係な別作品の必須条件にしない。指定がなければ姿勢8Hz・出力24fps、原稿の文字と控えめな効果音を初期案とする。画面比率と尺は原稿と用途から選ぶ。
- 作業先の指示と既存Remotion構成を確認する。原稿は保持し、永続素材・ソース・完成動画と、`tmp/` 内の試作・確認画像を分ける。

## コマと動作を設計する

コマごとに「何を伝えるか」「動かす箇所」「固定する箇所」「読む時間」を決める。反応の順番、無言の間、オチの静止を設計し、同じ上下動を全コマに反復しない。無音の口パクや原稿にないセリフ・表情を標準処理にしない。

[animation-and-review.md](references/animation-and-review.md) の方式選択と確認基準を使う。

- メッシュ：小さな首かしげ、うなずき、袖や指の移動。顔の内部は一まとまりで動かし、背景や文字への変形の漏れを抑える。
- レイヤー：前後の重なりが変わる動作、背景の直線がメッシュで曲がる場面。元の位置を消した背景、動く原画、静止した前景を分ける。手と持ち物は同じ変換を共有する。
- どちらでも原画を保てない場合は、動きの量・位置・方法を修正する。不足素材が必要ならその箇所と理由を示す。静止だけの動画を動作要件の達成と扱わない。

移動量は原稿サイズに応じて設定する。回転・移動の境界で新しい線、隙間、二重像を出さず、握りと接触点を保つ。画像の補完が必要なら利用可能な画像編集手段を使い、顔全体を再生成しない。

## 実装と試作

設定形式と実行コマンドは [config-and-runtime.md](references/config-and-runtime.md) を参照する。テンプレートは `assets/remotion-template/` にある。

```sh
python3 <このスキル>/scripts/create_project.py --project <作業先> --mode new
# 既存プロジェクトには --mode existing を使う
```

追加モードは独立した `src/manga-animation/index.tsx` と専用スクリプトを置き、既存のRoot、package.json、ロックファイル、動画を変更しない。依存不足・版違いを報告したら既存環境に合わせて必要分だけ整える。既存Studioへ統合する必要があれば、既存Compositionを残して個別に登録する。

原稿を配置し、設定を作品に合わせる。テンプレートの例画像をユーザーの完成作品に混ぜない。コマ切り出しは画素を保持し、文字と枠を欠かさない。色付き吹き出しを白で隠さず、対応する文字なし画像を使う。

```sh
node scripts/manga/prepare.mjs
node scripts/manga/validate.mjs
node scripts/manga/review.mjs
node scripts/manga/render.mjs
```

最初のコマに固定せず、使う処理を確認できる短い試作を選ぶ。顔、手と持ち物、遅れて出る文字、前景への出入りなど、異なる処理の初出を確認して本編へ反映する。同じ処理の確認を件数だけ増やさない。

## 確認、修正、納品

- 全コマの開始、各パーツの動作の頂点、文字表示の前後、終了を実画像で確認する。動作ごとに頂点が異なる場合も確認する。
- 圧縮前の画像で姿勢の保持を確認し、動く場面では次の姿勢への変化も確認する。動画は通し再生とファイル検査を行う。
- 顔、継ぎ目、握り、前景、背景の直線、文字、読む時間、持ち物の連続性を優先して修正する。音は実際の動作へ合わせ、音量と聞こえ方を確認する。未試聴など未確認の範囲を確認済みと呼ばない。
- 目視で見つけた問題を直し、その箇所と関連場面を再確認する。改善が進まず素材・手段・ユーザー判断が必要になったら、未達箇所と必要事項を示す。回数や指摘ゼロを品質の根拠にしない。
- 完成MP4をローカル動画として表示し、編集用ソースと再出力方法を示す。主な修正と確認の限界を短く伝える。公開・外部送信は制作とは別に扱う。
