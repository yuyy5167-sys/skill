# 画像一貫性ゲート

## 目的

既存記事修正時にも新記事作成時と同じ画像スキル、正本、画風、検品を使い、抽象的な独自プロンプトによる画風のずれを防ぐ。

## 1. 現行スキルを正本にする

画像工程の直前に `$education-blog-thumbnail-creator` の現行 `SKILL.md` と、適用する参照文書を全文読む。

- サムネイル: `style-grammar.md`、`diversity-quality-gates.md`
- H2画像: 上記に加えて `h2-heading-images.md`
- 人物を使う場合: `character-sheets.md`

本スキルへ画像プロンプト全文を複製しない。現行画像スキルの正本、参照役割、文字契約、停止条件をそのまま使う。

ユーザーが対象記事と画像修正を含む実装を承認している場合は、`authorization_mode: orchestrated_prepublication`、同じ `parent_run_id`、通知済みの記事パスと `images/` 保存先を渡す。この承認は未使用名への画像保存と対象記事の許可済み参照変更までであり、既存画像の上書き、別記事、Git、本番公開へ広げない。

## 2. 正本の役割を分離する

参照は次の役割で記録し、相互に代用しない。

- `character_sheet`: 人物同一性
- `style_example`: 完成画風、文字、余白
- `composition_guide`: 構図の発想補助
- `comparison_image`: 類似回避の比較

サムネイルでは登録済みの承認見本から必要な1〜2枚を実際に開く。ユーザーが特定の公開画像を今回の正本として示した場合は、その受諾記録、絶対パス、実測SHA-256を確認し、今回の `style_example` にできる。自動的に恒久登録はしない。

```yaml
reference_manifest:
  - path: ""
    role: style_example | character_sheet | composition_guide | comparison_image
    confirmation_status: direct_image_reference | viewed_and_transcribed | reference_unavailable
    sha256: ""
    inherited_features: []
    not_to_copy: []
```

必要な正本を開けない、役割が一致しない、人物正本が一意でない場合は生成しない。

## 3. サムネイルの生成前固定

次を確定してから生成する。

- 記事の中心メッセージ
- 一目で伝える意味
- 完全一致の日本語文字列
- 対象学年
- 人物の有無
- 主役モチーフ
- 構図と読む順番
- 焦点位置と8%安全余白
- 入れてはいけない事実・ロゴ・疑似文字
- 正本から継承する画風
- 正本から転用しない人物位置、動作、小物、背景構造

`教育系、水彩風、クレヨン風、やさしい雰囲気`だけでは設計完了にしない。

```yaml
pre_generation_review:
  result: pass | revise | blocked
  problems_found: []
  corrections_applied: []
  unresolved_problems: []
```

`result: pass`、完全な `reference_manifest`、固定コピーがそろうまで `$imagegen` を呼ばない。

## 4. 維持する標準画風

- 明るく温かいクリーム系背景
- 深いネイビーまたは濃いグレーの細く明瞭な輪郭
- コーラル、ミント、淡い黄色、淡い水色の柔らかなフラット塗り
- 線画95・水彩5
- 水彩は背景紙と色面内部だけ
- 日本語、顔、主輪郭、細い図解線はデジタル印刷のようにシャープ
- 主見出しと補足の強さを分ける
- 画像単体でテーマと読む価値が一続きの意味として分かる
- 人物、教材、文字、小物が部品の寄せ集めではなく一つの場面として成立する
- 単なるタイトル表示に見えない、内容に必要な情報量を持つ

禁止する表現:

- 全面水彩、輪郭外のにじみ、大きな筆跡、スプラッシュ
- クレヨンのような強い擦れ、かすれた日本語、ぼやけた輪郭
- 全文字を同じ最大サイズ・極太にする
- 関係のない小場面をばらばらに並べる
- 内容不足を装飾だけで補う
- 写真調、3D、強いアニメ塗り、重い影、強い光沢
- 未確認の料金、日付、順位、評価、キャンペーン、ロゴ、サービス画面

ユーザーが別画風を明示した場合は、その記事だけで指示を優先する。

## 5. H2画像の分離契約

H2画像は画像スキルの `h2_style_profile_v1`、現行revision、実測 `style_profile_sha256` を文章契約として使う。

- 画風見本、完成サムネイル、過去H2画像を生成へ直接渡さない。
- サムネイルから引き継ぐのは線、背景温度、配色、文字感、水彩強度の文章化した差分だけである。
- 構図、人物位置、小物、読む順番はH2本文から新しく設計する。
- 各H2の要点を大きな短い日本語1〜2ブロック、最大3ブロックへ固定する。
- 指定外文字、疑似文字、ロゴ、透かし、小さな説明文を追加しない。
- 隣接H2で同じ構図が続く場合は、主役、焦点、読む順番、背景、人物の有無・動作から実質的な違いを作る。

ユーザーが既存画像を優先したH2は生成対象にしない。生成対象だけを画像スキルの `render_from_plan` で1資産ずつ実現できる。既存画像優先の明示条件を、新記事既定の全H2生成で上書きしない。

`render_from_plan` を使う場合、本スキルが親として、設計版、asset_id、request_id、`style_profile_sha256`、最終プロンプトが完全一致し、生成前レビューが合格した資産だけへ内部の `generation_approval` を返す。これはユーザーへの追加確認ではなく、承認済み1記事内の機械的な実行ゲートである。不一致や設計変更時は旧承認を使わない。

## 6. 生成後の実物検査

画像そのものを開き、次を確認する。

- 固定日本語が1文字ずつ一致し、余分な文字がない
- 文字と主輪郭がシャープ
- 水彩が背景紙と色面内部だけにある
- 学年、人物数、表情、手、姿勢、小物が設計どおり
- ロゴ、透かし、未承認情報がない
- 中心、文脈、補足の読む順が明確
- 正本と比べて線、文字、配色、余白、場面の一体感が一致
- 正本の配置・人物・小物を無批判に複製していない
- 画像単体で記事テーマと要点を再記述できる
- 簡素すぎる場合は、不足する意味を特定し、装飾だけを追加しない

実物を見ずに、プロンプトやファイル形式だけで合格にしない。

## 7. 違和感を指摘された場合

ユーザーから「いつもと違う」「シンプルすぎる」「これまでの感じではない」と指摘された場合は、画像を変更する前に次を比較する。

1. 実際に使った正本と参照状態
2. 線の太さ、鮮明さ、水彩・クレヨン強度
3. 日本語の太さ、色、文字階層
4. 配色と余白
5. 情報量と一目で伝わる意味
6. 一体化した場面か、部品の寄せ集めか
7. 記事内容とモチーフの一致
8. スマホ表示での可読性

観測した原因、変更する点、維持する点、副作用をユーザーへ説明してから修正する。分析前に再生成しない。

## 8. 保存と反映

- 既存ファイルを上書きせず、版付きの未使用名へ保存する。
- 公開用は1536×864、16:9、WebP、300KB以下を目標とする。
- 500KB超は再圧縮し、文字と輪郭を再確認する。
- 生成対象の全H2画像が合格するまで記事参照を変更しない。
- 1枚でも不合格なら、部分反映の明示指示がない限り一括反映を止める。
- `coverImage`変更は記事親工程が行い、画像スキルへ無断で拡張しない。

## 9. 実表示

サムネイルは画像単体に加えて実際の記事カードを320、375、390、768、1280pxで確認する。現行CSSの切り抜きと焦点位置を含め、文字と主役が残ることを確認する。

H2画像は本文幅の同じ5幅で、全体、文字、数字、矢印、主役、縦横比、横はみ出しを確認する。

`coverImage`変更時はカテゴリ一覧、新着一覧、関連記事カードが新しい画像を実際に読み込むまで完成扱いにしない。
