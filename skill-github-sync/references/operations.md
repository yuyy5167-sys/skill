# 同期の運用

## 実体・保存先

`inventory` は登録と現在の候補を出す。同じ実体の入口は一つにまとめる。新しい保存先はbeginで追加する。`.system`・配布元のキャッシュの自動更新は除外し、ユーザーが明示的に編集を依頼したものは永続的な実体を個別登録する。

スキル内の関連ファイルを扱う。認証ファイル、キャッシュ、ログ、一時ファイルを除外する。内部リンクが範囲外を指す場合は停止する。スキル外の共通実装は同期されたとは扱わず、必要なら依存として明示的に登録する。

登録範囲に初期差分がある場合は、その対象一覧を示す。初回に保存する対象として承認済みのスキルには `begin ... --bootstrap` を使い、現在のローカル版を検証してready・syncする。bootstrapは追加・更新だけを扱い、GitHubにだけある旧ファイルを自動削除しない。初期の同期を終えてから通常運用へ進む。

## 状態と再開

`status` で結果を確認する。通信障害はRETRY_PENDING、認証・権限・同一パスの別更新はNEEDS_ACTION。完成版は保持される。

送信が許可された次のスキル編集完了時はsyncを呼ぶ。ユーザーが再試行を依頼した場合は `retry ... --send-allowed` を使う。NEEDS_ACTIONも再比較するが、競合が残れば再び停止する。通常の質問だけのチャットから待機列を送らない。

pushの失敗後はリモート確認が先。送信済みなら同じ内容のコミットを追加しない。対象外の別更新は保ったまま最新mainから変更を組み直し、対象パスの別更新は自動で消さない。確認したmainの版と時刻を記録する。確認後の外部変更まで固定する保証はしない。

同じ実体がEDITINGなら、当該処理を再開してreadyにするか、ユーザーが取消しを求めた場合に `cancel --job <id>` で取り消す。編集開始時点の未登録差分は取り込まない。新しいセッションだからという理由だけで編集中の記録を破棄しない。

取消した先行処理がある後続処理は比較基準の確認が必要。後続も取消し、ユーザーが保存する版を明示した後にbeginで登録し直す。送信済みのコミットはcancelで消さない。

## 保存内容とロック

送信は既存 `.skill-github-sync` の手動作業を含まない一時作業コピーから行う。完成版・コピー先・ステージのblob・リモートblobを照合する。Windowsの改行変換を一時コピーの管理パスだけで抑え、元の設定を変えない。強制push、全体のgit add、無条件のミラー削除を使わない。

同期と状態更新の排他はOSのファイルロックを使う。所有プロセス終了時にOSが解放するので、生きたロックの時間切れ破棄をしない。編集の所有は処理ID・セッション・EDITING状態で保持する。

未反映の完成版は自動削除しない。確認済み処理の一時作業コピーを整理する時は、解決した絶対パスが状態フォルダのwork内であることを確認してから、その処理のコピーだけを削除する。

## フック・有効化

ユーザーの `~/.codex/hooks.json` のUserPromptSubmitとStopに、絶対パスのPythonと本スクリプトの `hook` コマンドを設定する。timeoutは10秒。フックはネットワークを使わず、取得不足を知らせる。既存のプロジェクトフックは保持する。

新規・変更されたフックは現在の定義をレビューして信頼登録する。信頼を迂回するオプションは使わない。フックのロードと動作が確認できるまでは補助を有効と報告しない。設定変更後は新しいターン／チャットで比較基準の取得を確認する。

公式仕様： https://learn.chatgpt.com/docs/hooks
