# レビューと修正

## メインと独立した担当

メインエージェントは依頼、採用設定、全ページの因果、修正範囲を管理する。サブエージェントの指摘は候補として扱い、実画像・原作・ユーザーの目的に照らして採否を決める。

複数ページ作品ではサブエージェントが利用可能なら独立した読者役を使う。教育内容や小物が複雑なら教育・作画担当も分担する。人数を固定せず、モデルは依頼の指定を優先する。利用できないレビューを実施済みとしない。会話・設計を担当するモデルと、実際に画像を描く生成モデルを混同しない。

初見読者役は会話履歴を引き継がない新規エージェントとして起動する。`spawn_agent` を使う場合は `fork_turns="none"` を明示し、既定の全履歴引き継ぎを使わない。完成画像と読む順序・表示方法だけを渡し、台本、作者の説明、期待する解釈、既知の指摘は先に渡さない。「何が起きたか」「なぜ次の行動になったか」「最後に何が変わったか」「どこで読み返したか」を聞く。台本を渡して説明を確認したレビューを、初見画像レビューと呼ばない。

教育担当には元記事と台詞・画像を渡す。作画担当には採用人物と前後ページなど、連続性を確認するための資料を渡す。同じ担当が既に台本を知っている場合、初見読者には別の担当を使う。

## 生成前・各ページ・作品全体

生成前は因果、台詞の自然さ、学習内容、読順、ページ間の接続を確認する。設計の合格は画像の合格を意味しない。

各ページの生成後に実画像を表示し、次を当該作品に必要な範囲で確認する。

| 観点 | 実画像での確認 |
|---|---|
| 因果と接続 | 前の出来事に対する反応・行動として次が読めるか |
| 台詞と話者 | 原文があるか、誰の発言か、問答の順序が自然か |
| 無言の間 | 視線や動作から意味が分かるか |
| 人物 | 顔、髪、頭身、服、左右の特徴が採用設定と一致するか |
| 手と小道具 | 持ち手、数、位置、移動、書き込みが前後で成立するか |
| 読順と文字 | コマ・吹き出しが自然に読め、向きと内容が正しいか |
| 教育内容 | 数式・英文・AIの動作が正しく、原作の主張を誇張していないか |
| 回収 | 最後の行動・反応が、それまでの出来事につながるか |

重要な紙や画面の文字は原寸で確認する。全ページ完成後は連続して読み、スマートフォン相当の表示幅でも台詞と表情を確認する。プレビューは全ページの読み込み、順序、横へのはみ出し、必要な原寸表示を確認する。見られない文字や画像は確認済みにしない。

## 原因に合わせた修正

- 断絶があるなら、次ページの冒頭に前の行動への反応を入れる、場面移動を示すなど因果を直す。説明を後のページへ足すだけで読者の混乱を放置しない。
- 問答が逆なら、コマまたは吹き出しの順序を直す。コマの交換のために画像全体を鏡像反転させない。
- 台詞が欠けたなら必要な台詞と話者を復元する。文字の失敗を隠すために「無言の演出」に変更しない。
- 小物が増えた、持ち上げた紙が机に残った、後の答えが既に書かれている場合は、該当状態を直し前後ページを確認する。
- 人物の比率や表情が変わった場合は、採用プロフィールを参照して必要箇所を直す。別人物や新衣装へ勝手に変更しない。

画像の修正は既定で内蔵 `image_gen` を使う。編集前に対象画像を確認し、保持する部分と変える部分を明示する。ユーザーが別の手段を指定していない限り、Python等の画像編集へ無断で切り替えない。文字が直らない場合は問題と選択肢を報告し、台詞削除で完成扱いしない。

## 反復と完了

修正依頼は当該作品の制作データに、内容・原因・変更箇所・再確認結果を短く記録する。単発の好みを全作品共通の規則に変えない。修正後は変更したコマ、隣接ページ、必要なら全作品を読み直す。

回数・指摘数・点数を品質の代わりにしない。十分な初稿に不要な変更を加えず、重要な不足があるなら必要な修正を続ける。意味のある改善が止まる、指示が矛盾する、採用人物や資料が未確定、必要な生成・確認手段がない場合は残る問題と必要な判断を報告する。画像を見ずに「ループした」「自然に読める」と断定しない。

完成は、依頼されたページがそろい、実物全体を確認し、重要な不足が残らず、順に読める成果物と再編集データが渡せる状態を指す。面白さを全読者へ保証せず、読めた構造・反応・ユーザーの希望との一致を根拠に説明する。
