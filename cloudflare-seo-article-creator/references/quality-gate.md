# 品質ゲート

## 判定原則

点数の平均ではなく、適用対象の必須条件がすべて合格した場合だけ次工程へ進む。実行していない検査を合格にしない。アフィリエイトは`eligible`、`not_applicable`、`deferred`、`blocked`を条件から判定し、承認済み契約が実際にない`deferred`だけを専用の保留状態とする。

文字数・見出し数・出典数・表の数を内容品質の代替にしない。主要な疑問ごとに、回答のある本文箇所と根拠・条件を受入証跡に残す。依存スキルのPASSや「具体的・読みやすい」という自己評価だけで合格にしない。内容品質、ビルド、実表示は別々に判定する。

## G1 調査

- [ ] 検索背景・主質問・読後の到達点を仮説として作り、調査目的・疑問・根拠・条件を定めた
- [ ] 反証・追加疑問を含む完全レポートを読み、結論を左右する原資料を確認して記事方針を確定した

- [ ] キーワードと新規記事作成指示から`orchestrated_prepublication`承認を記録した
- [ ] 記事ID、予定パス、作成物、作成理由、`draft: true`、上書き・公開禁止を開始時に通知した
- [ ] 指定キーワードをGoogleで直接確認した
- [ ] 調査日時、条件、順位、URL、本文確認状況がある
- [ ] 検索意図、ペルソナ、競合差分、一次情報、未確認事項が根拠付きである
- [ ] 回答の充足とは別に、キーワード・読者・公式情報から重要な疑問の見落としを検収し、除外した重要候補には理由がある
- [ ] 主質問への回答または確認限界が、`answer_map`の出典・条件・確認状態に対応している
- [ ] 数値の対象・時点・適用条件と、公式説明／記事側の解釈を区別した
- [ ] 未確認事項・矛盾の結論への影響を判定し、ワークフロー2.5の進行条件を満たした
- [ ] 追加調査が完全な上流レポートに反映され、回答表と一致する
- [ ] ユーザー未提供の体験・成果・専門性を創作していない
- [ ] 新規作成として進められる推奨状態である
- [ ] 同名記事ルートまたは既存ファイルがない

1件でも満たさなければ見出しを作らない。

## G2 見出しと記事設計

- [ ] 見出しスキルを直接実行して`status: PASS`とし、タイトル文言・見出し文言・順序・役割を確定した
- [ ] タイトル、H1、H2、H3に安定IDと根拠があり、各H2に`reader_question`と`reader_outcome`がある
- [ ] H1と本文H2/H3の役割が分離されている
- [ ] 内部リンク意図が`plan`済みである
- [ ] 3タイトル候補を比較し、合格した推奨案を自動採用した
- [ ] `title_contract`に推奨タイトル、採用タイトル、一つの`core_promise`、本文へ移した`supporting_topics`があり、3候補の個別ゲートと親の初見判定がすべて合格した
- [ ] 採用タイトルが区切り記号で補足論点を詰め込まず、一つの中心的な読者価値を約束している
- [ ] タイトル、構成、結論、内部リンク意図が現在の一括承認に結び付いている
- [ ] 検索者・サービス利用者・主要評価軸を分け、検索意図と一致した評価軸を採用した
- [ ] 各主要見出しの`required_answer_ids`が実在する回答に対応し、未確認事項を確認済みのように約束していない
- [ ] 複数章が同じ回答を繰り返す設計ではなく、固定の学習動作を全記事へ押し込んでいない
- [ ] 問題台帳・採用理由・詳細な根拠説明を先に見ず、対象キーワード、主検索意図、ペルソナ、タイトル、H2、H3だけで読者価値を再確認した。同一実行者の確認を独立検証と呼んでいない
- [ ] 主質問への答えまたは判断の入口が、論理的に置ける最も早いH2にある
- [ ] 各H2から、読者が得る答え、判断材料または次の行動を説明できる
- [ ] H2・H3が執筆者の確認・調査・検証作業の羅列になっていない
- [ ] 未確認事実、根拠のない効果・優位性・煽りで興味を補っていない
- [ ] 設計不合格時は見出しを修正し、根拠と読者価値を再確認した。依存スキルの出力が確定構成を独自変更していない

入力不足で記事の目的が変わる場合、または既存記事への統合・リライトが推奨された場合は本文を完成させない。

## G2.5 実装計画とTODOの完了管理

- [ ] メインキーワードと明示的な記事作成指示があり、既存記事ではないことを確認したうえで、1記事分の`orchestrated_prepublication`一括承認として記録した
- [ ] 計画、タイトル、調査、執筆、公式画像、サムネイル、各H2見出し画像、保存、検査、修正、隔離プレビューについて、一括承認範囲内の途中承認を追加していない
- [ ] 計画書、TODO、進捗、検収結果を進行共有として扱い、返信待ちの承認ゲートにしていない
- [ ] ユーザーが停止を指示した場合は安全な区切りで止め、範囲外の権限またはユーザー判断が必要な場合だけ`blocked`にした
- [ ] 本文・リンク・公式画像・UI化・保存・サムネイル・各H2見出し画像・検証・プレビューを対象とする内部計画がある
- [ ] 計画に対象範囲、対象外、固定事項、成果物、一括承認範囲、依存関係、停止条件、検証・完了条件、計画バージョンと更新条件がある
- [ ] TODOごとにID、目的、入力、依存関係、許可範囲、成果物、受入基準、検証、状態、根本原因、連続回数、構造的再設計回数、再検証範囲、停止理由、再開条件がある
- [ ] TODOが単独で検証できる成果物または判定の単位で、同じ成果物への連続編集など強く依存する作業を実行前にまとめている
- [ ] 実行開始前に、精密な計画書とTODO一覧をユーザーへ提示し、個別承認を追加条件にしていない
- [ ] 全TODOを本スキルが直接実行し、別実行者への分担やモデル別の分担を使っていない
- [ ] TODOを依存順に実行し、同じ記事ファイル、画像、記事設計データに関わる作業を前工程の検収前に進めていない
- [ ] 各TODOについて、成果物・差分・検証証跡を確認して受け入れた
- [ ] 見出し構成TODOの受入証跡に、見出しスキルのPASS、見出しだけの初見読者価値検収、完全な根拠による正確性検収、`reader_question`・`reader_outcome`、執筆作業中心でないこと、読者価値の非回帰がある
- [ ] 設計不備は設計TODOへ、制作不備は該当TODOへ、観測した問題・固定事項・再検証条件を付けて戻した
- [ ] 正確性が改善しても読者の疑問、読後の到達状態、具体性または次の行動が失われた場合は、回帰として受け入れなかった
- [ ] 根本原因の連続回数と構造的再設計回数を原因変更時・受入時にリセットし、同じ原因が2回続いた場合は構造的な再診断と計画更新を1回だけ行い、それでも残る場合は`blocked`として根拠と再開条件を示した
- [ ] 計画変更時に、理由、影響、変更TODO、再検証範囲、計画バージョンを更新し、表現修正だけでは版を増やしていない
- [ ] 各制作TODOに設計版・目的・固定事項・制作順・裁量・禁止・受入基準を持つ実行記録がある
- [ ] 必須設計不足では制作せず`needs_execution_input`として原因工程へ戻し、任意情報の不足だけでは停止していない
- [ ] 旧版成果物は最新設計との差分と影響を判定し、影響なしの受理理由または再検証範囲を残した
- [ ] 必須TODOがすべて`accepted`で、非アフィリエイトの未解決TODOがない

正本データ、権限、依存ツールの不足などで合理的に解消できない場合は、該当TODOを`blocked`にし、理由と再開条件を示す。通知済み記事ルート外への書込み、既存ファイル変更、公開権限が必要な場合も`blocked`にする。

## G3 本文

- [ ] 本文作成中に見出しを無断で追加、削除、変更、並べ替えていない。変更が必要なら原因工程へ戻し、再受理した見出しを使った
- [ ] 全本文単位が`section_pass`
- [ ] 全文が`article_pass`
- [ ] 使用可能な根拠を超える断定、因果、数値、比較を追加していない
- [ ] 読者を責めず、煽らず、平易な日本語である
- [ ] 導入、各節、結論が同じ中心課題へ対応している
- [ ] 導入と各節を、確認日や「公式で確認した」という制作報告の定型文から始めず、読者の主質問への答え・発見・判断材料から始めている。必要な確認日は対象情報・出典と対応づけ、同じ注記を反復していない。適用時期、申込期限、調査実施年を落としていない
- [ ] 各見出しの疑問・到達点と配下本文が一致し、不一致の原因が設計なら設計を直し、本文制作なら該当TODOへ戻した
- [ ] 主質問と確定した評価軸に沿い、教材利用の評価を行う箇所で学習動作・教材の支援・残る不足を説明している
- [ ] 検索意図と関係のない保護者管理論へ置き換えず、支援未調査のまま家庭の努力へ解決を委ねていない
- [ ] 主要な疑問の本文回答箇所と出典・条件を確認し、内容品質の検収証跡がある
- [ ] `emphasis_plan`が空でなく、章・回答ID・短い完全一致語句・役割・理由を持ち、固定件数、段落全体、同一語句の反復、装飾目的の強調になっていない
- [ ] 主要回答を強調しない場合は`not_emphasized`に理由があり、重要な結論・条件・期限・注意・行動が流し読みで失われない
- [ ] [改善前後の参照例](content-quality-examples.md)を踏まえ、以下の不合格条件に該当しない

| 不合格条件 | 観測する不足 |
| --- | --- |
| 回答不足 | 見出しの疑問に本文が答えていない |
| 一般論への置き換え | 商品名を替えても主要な説明がそのまま成立する |
| 調査の読者任せ | 記事側で調べられる事実を「公式で確認」で済ませる |
| 意味の重複 | 別章で同じ判断・助言を繰り返す |
| 努力への責任転嫁 | 支援を調べず本人や保護者の努力を求める |
| 数字の羅列 | 数値・機能の読者への意味が不明 |
| 根拠を超える断定 | 条件や対応範囲を超えて効果を保証する |
| 評価軸の逆戻り | 検索意図より固定の学習動作・管理論を優先する |

商品名の置き換えは補助診断であり、必要な一般解説を一律に落とさない。「確認できない」という回答もG1の調査範囲・影響・限定条件を満たせば扱える。本人の個別条件・変動情報の確認案内を禁止するものではない。重要論点は事実・意味・限界をつなぐが、全段落で同じ型を強制しない。

不合格はワークフローの原因別差し戻し表に従う。`needs_execution_input`や未確定本文を後工程へ渡さない。

- [ ] 新規記事の毎回の実行で、画像の要否にかかわらず依存スキルを直接実行した
- [ ] 内部リンク済み完成本文を読み取り専用で依存スキルへ渡した
- [ ] 本スキルの実行では`authorization_mode: orchestrated_prepublication`と通知済み保存先を渡した
- [ ] `evidence_policy.required: true`、探索時`capture_mode: analyze_final_body`、取得時`explicit_requests`、`strategy: screenshot_preferred`と方法順・上限・試行必須条件を渡した
- [ ] 完成本文から視覚化候補を優先順位どおり最大3主張まで抽出した。該当なしの場合は根拠付き`NOT_APPLICABLE`である
- [ ] 候補探索中にファイルを作成していない
- [ ] 保存候補ごとに元ページ、情報源区分、対応主張、権利根拠、希望取得方法、実際の取得方法、試行結果、加工方法、予定ファイル名、絶対保存先を記録した
- [ ] 視覚化すべき主張と権利条件を満たす公式候補がある場合、`capture_attempts`に1件以上の試行記録がある
- [ ] `element_screenshot`、`pdf_region_capture`、`viewport_screenshot`、`direct_download`の優先順を守り、フォールバック理由を記録した
- [ ] 本スキルの実行で保存した画像は一括承認の`article_root\images\evidence`内にある
- [ ] 単独利用で保存した画像は、提示内容どおりユーザーが承認した候補だけである
- [ ] 個人ブログ、一般の第三者ブログ、広告・タイアップ、アフィリエイト主体の記事を情報源にしていない
- [ ] 保存画像の権利状態が`allowed`で、ローカル保存と記事掲載が許可されている
- [ ] 保存成果物ファイルは画像だけで、記事本文、Markdown、画像参照、キャプションを変更していない
- [ ] 全画像のパス、SHA-256、MIME、寸法、出典、権利、対応箇所、取得方法、モバイル確認を保持している

- [ ] 取得機能の不足や2回の取得失敗を`READY_WITHOUT_ASSETS`で隠していない
- [ ] `evidence_result.status`が受理可能状態で、根拠となるdiscoverまたはcapture出力を改変せず保持している
- [ ] 次工程が画像を使う場合、スキーマ、パス、SHA-256、掲載・加工可否、帰属表示を再検証した
- [ ] 配置画像は対応見出し・主張、alt、帰属表示、モバイル可読性、現行Astro Markdownとの整合が確認できる

## G5 アフィリエイトと外部リンク

共通条件:

- [ ] 仮URL・プレースホルダーがなく、アフィリエイトCTAを内部リンクへ混ぜていない
- [ ] 本文リンクを`internal`、`affiliate_cta`、`generic_official_navigation`、`task_required_official`、`evidence_reference`へ分類した
- [ ] 進研ゼミCTAが`eligible`の場合、同じ公式講座トップへ単に誘導する`generic_official_navigation`が0件である
- [ ] 本文に残す公式FAQ・規約等は、手続き・交換・ログイン等に必要なURLと理由を`allowed_external_links`へ記録している

`eligible`:

- [ ] タイトル、想定読者、結論、承認済み設計が同じ講座を示す
- [ ] 自然な配置章と`shinken_zemi_cta_v1`の共通CSSを現在実行で確認した
- [ ] 子スキルの承認済み講座別CTAを1件だけ挿入し、`affiliate_link_manifest`を保持した
- [ ] 最終HTMLのURL、計測画像、属性、固定DOM、対象講座、重複、320・375・390・768・1280px表示を`audit`し、`pass`である

`not_applicable`:

- [ ] 複数学年、講座横断、対象不明、または次行動を案内しない理由を記録した
- [ ] 記事範囲をCTAのために変更せず、CTAが0件である

`deferred`:

- [ ] 記事に必要な承認済みアフィリエイト契約が実際に存在しない
- [ ] `reason_code: affiliate_inventory_pending`、CTA 0件、再開条件を記録した

講座不一致、未承認URL、共通部品欠落、挿入・監査不合格は`blocked`であり、G5を合格にしない。

## スキル改修時の挙動検証

この節はスキル改修時の試験用で、通常の記事ごとに全試験を課すものではない。構文検査合格だけで品質の再現性を保証しない。実施しなかった試験は未実施と記録する。

試験前にキーワード、主要な疑問、利用ツール、入力資料、スキル版、評価者・方法、実施回数、許容修正回数、合格条件を固定する。初期案は教材評価・料金変更・手続きの3種類を各2回、別の実行で試し、各実行の修正は既存停止条件に加えて2回までとする。これは試験範囲の上限で、通常ループの上限変更ではない。結果を見てから有利な設定へ変更しない。

| 試験 | 確認すること |
| --- | --- |
| 執筆 | 同じ根拠資料・目的から必要な回答を含む本文を書けるか |
| 調査込み | キーワードから重要な疑問・根拠を拾い記事を完成できるか |
| 不合格検出 | 条件欠落、一般論、重複、根拠のない断定を具体的に指摘して止められるか |

不合格検出は欠陥入り原稿と適切な原稿を含める。欠陥の正解は評価側だけが持ち、事前に渡さない。改善例に使っていないテーマを含め、条件名を伏せるだけで客観性が保証されたとしない。

各記事で主要疑問すべてに回答または確認限界があり、判断を誤らせる事実誤認・条件欠落・根拠のない断定が0件、出典を追跡可能、主要章が一般論・反復だけでなく、許容修正範囲内でG3を満たすことを確認する。不合格検出では用意した欠陥の箇所・理由を指摘し、適切な原稿の不合格にも根拠を求める。平均点で重大欠陥を相殺しない。

事実は出典へ戻って評価し、時間、修正回数、未解決事項、評価者を記録する。ユーザーによる読み比べを含む各評価の実施有無を分け、同一実行者の自己検収を独立した品質保証と呼ばない。試験の成功は確認した条件・テーマ・回数に限定して報告する。

### 直接実行の接続試験（2.6）

形式検査と次の実際の依存スキル接続試験を区別する。新規記事の全生成、画像生成、実カード検査を未実施ならその段階を未検証として報告する。

| 入力・状況 | 受入条件 |
| --- | --- |
| 読者仮説に反する調査結果 | 根拠を確認して設計を修正し、反証を削除しない |
| 本文作成に必須回答または根拠が欠ける | 推測で執筆せず、原因工程へ戻す |
| 見出しや結論を変更した依存スキル出力 | 検出し、設計または制作原因を判定して再検証する |
| UI設計と記事型の既定が異なる | 設計を再推定せず指定部品と構成を実装する |
| 画像候補探索だけを依頼 | 保存せず候補を返し、captureは選定した対象だけ取得する |
| サムネイルの確定コピーと別文言の生成要求 | 設計と照合できず、生成しない |
| 新規記事の画像工程で`thumbnail_only`が渡された | `thumbnail_and_h2`へ戻し、全H2画像の完成条件を復元する |
| H2画像の一部だけが合格または保存された | 記事へ部分挿入せず、全件の再検査または停止状態へ戻す |
| 推奨タイトルとfrontmatterのタイトルが異なる | 静的検査で失敗し、`title_contract`へ戻す |
| タイトルが補足論点を区切り記号で詰め込む | 文字数だけで合格にせず、`core_promise`を一つにして見出しスキルの全タイトルゲートを再実行する |
| `emphasis_plan`の語句がUI化後に太字でない | 静的検査とDOM確認で失敗し、UI工程へ戻す |
| 進研ゼミ小学講座が一意でCTA共通部品も存在する | `eligible`として小学講座CTAを1件挿入し、最終監査する |
| 複数講座を扱う進研ゼミ記事 | `not_applicable`としてCTAを追加せず、記事範囲を狭めない |
| `eligible`なのに同じ公式講座トップへの通常リンクがある | 許可外リンクとして失敗し、CTAと競合する通常リンクを除く |
| 公式FAQが手続きに必要で許可URLと理由がある | 通常リンク0件を強制せず、`task_required_official`として保持する |
| 設計版更新後に旧版成果物が到着 | 差分と影響を記録し、影響箇所を再検証する |
| 新しい方式を指定しない単独利用 | 依存スキル従来の一貫実行と保存承認を維持する |

サムネイルとH2見出し画像の実画像試験は依存スキルの改訂時生成試験に従う。試験画像を既存記事や承認見本へ自動反映しない。
